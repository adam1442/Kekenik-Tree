# Changelog

All notable changes to this project are documented here. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project follows
[Semantic Versioning](https://semver.org/).

## [Unreleased]

### Changed
- **Sample projects replace the species presets (T19).** The 19 generated species presets (`src/presets/species.ts`, `builder.ts`, `seasons.ts`) are removed. The built-in Library, the Welcome window and the thumbnails now list six real projects stored in `public/Sample Projects/`: Oak, Birch, Palm, Fern, Grass and Swamp (`src/presets/samples.ts`). Vite copies the folder to `dist/Sample Projects/`; a sample is fetched only when it is opened or its thumbnail is rendered (about 32 MB in total, so they are not inlined into the single `index.html`). Library categories are now Broadleaf, Palm & Tropical, Shrubs & Plants and Special; thumbnail cache revision `s1`.
- **A new project contains the Tree node only (T19).** `defaultGraph()` (startup, File > New, closing the last document) returns the `output.tree` node and nothing else: no generator, force, material or edge. The old Tree > Trunk > Branches > Leaf starter graph survives only as the test fixture `tests/fixtures/starterGraph.ts`.
- Tests moved from the species presets to the samples (`tests/helpers/sampleProjects.ts`); `tests/presets.test.ts` checks every sample (registry validity, round trip, LOD 0 / 3, determinism, budget) and the realism report (`qa/realism-report.md`, `qa/baseline.json`) is generated from the six samples.

### Added
- **T18 completion.** The export wind seam audit now runs on every exported LOD (`windAuditLods`, per-LOD warnings and dialog rows); packed maps can be written as DDS with the full mip chain (*Packed format*, `src/export/images/ddsWriter.ts`), so the AlphaIsOpacity / RgbIsNormal mip flags reach the engine; *Reset Lightmap* also resets the Unwrap scale of project library materials. Tests added to `tests/exportParity.test.ts`.
- **Export parity for real-time use (T18).** Wind seam audit of the export meshes (report + `.kekenik.json` + warning above `1e-3 x height`), reference GLSL for `_WIND_*` in docs/EXPORT_SPEC.md. Data-driven texture packers (Kekenik default, Unity URP, Unreal) with Force textures and mip flags (RgbIsNormal / AlphaIsOpacity) chosen in the export dialog (default `legacy` = unchanged). Export option V-tiling (whole V repeats per tiled primitive, U tile count warning, resolution loss estimate). Branch *Create seams* (`uvCreateSeams`: doubled ring vertices at whole U tile borders, welded mesh unchanged). Lightmap UVs: Tree > Lightmap (Enabled / Resolution / Layout Atlas or UDIM), per-generator Lightmap weight (leaves 0 = one texel per leaf), per-material Unwrap scale, packer that fits the resolution and reports the texel density, view mode *Lightmap density*, command *Reset Lightmap*. Material Atlas handling gets *Force out*. `tests/exportParity.test.ts`.
- **Vertex Color Mode on Leaf / Frond / Decal / Fin / Cluster (T17b).** Material > Vertex Color now has **Mode** (Inherit / Multiply / Set / Add), **Mode color**, **Seamless**, **Profile** (along the leaf / frond / patch) and **Parent curve** (by the attach point on the parent; a frond follows the curve along the parent range it covers). They come from the same builder as the tube generators (`vertexColorParams(items)`) and the same maths (`itemColorFn` -> `modifyColor`); the existing Variance stays the single per-item variance. Every leaf, frond, decal and fin writes its own random tint to `branchTint`, so the Kekenik R channel is no longer a constant 0.5 there. Vertex colour R / G / B views keep the alpha cut-out of leaf cards (basic material with the alpha map / alpha test of the base material, raw values). `mergeMeshData` keeps `branchTint` when only some parts have it (missing parts read 0.5). Neutral defaults keep the old colours (tested).
- **Procedural vertex colours (T17).** Tree > Vertex Color: **Compute** (default on = earlier behaviour; off drops the colours from exports) and **Packing** (Legacy = RGB albedo tint x AO as before, Kekenik = R per-branch random tint, G height 0 base .. 1 top over the whole plant, B ambient occlusion). Every tube generator (Branch / Trunk / Root / Knot) gets Skin > Vertex color: **Mode** (Inherit / Multiply / Set / Add), **Color**, **Variance** (deterministic per branch), **Seamless** (colour at the attach point equals the parent's exactly) and the **Profile** / **Parent curve** strength curves (`src/geometry/vertexColor.ts`, one reader `readVertexColorOptions`). Viewport view modes **Vertex color R / G / B** (Alt+Shift+R / G / B; the packing is decoded in a shader, `ao` shows the analytic AO) and the Vertex color mode decodes Kekenik packing. Export: the packing is written to glTF COLOR_0 / OBJ / PLY colour columns, new AO bake mode **Bake AO into vertex colour B**, the manifest lists the channel meaning. Meshes carry a new optional `branchTint` attribute. Defaults are neutral (legacy colours bit-identical, tested). `tests/vertexColors.test.ts`.

- **Geometry forces and new force types (T16).** New Force nodes Gnarl, Twist, Planar, Return, Knockout and Geometry (Mesh asset: Avoid / Attract / None, Collide None / Obstruct / Prune / Stop, Range, Falloff, Skin; CPU triangle BVH with closest point, ray hits and inside test in `src/forces/geometry/`). Common force properties Align strength, Indicator scale and Attenuation (enabled / centre / radius / falloff); generators get Forces > Align. Knockout forces attached to a generator remove nodes growing in the arrow direction (generation env). Force gizmos for the new types, cycle-guard helper for a future Generators source. `tests/forcesParity.test.ts`.

### Fixed
- **Steering forces turned branches sideways (T16).** The steer solver rotated a segment about the steering vector instead of towards it (Phototropism with light (1, 0, 1) bent a vertical stem towards -Y). Steer forces (Phototropism, Attractor, Vortex, Curl, Pull to Axis, Ground avoid, Collision) now turn towards their field; existing projects using them will look different (correctly).

- **Decal and Fin: cutout-mesh support; Decoration generator removed (T15, pass 2).** A Material row with a cutout mesh gives a decal or fin the cutout's outline (refined, then projected onto the skin / mapped with fold, curl, noise and wind exactly like the grid; height fades to 0 along the outline; the cutout's anchors are exported). One shared `PlanarShape` (`src/generators/surfaceDetail`) replaces the grid-only loops. The old *Decoration* generator is gone: projects that contain one still open (the node is dropped and its children stay attached to its parent); use Decal, Fin, Leaf or Mesh instead.
- **Decal and Fin generators (T15).** New `generator.decal` (flat patch projected onto the parent skin: Size + % of parent, Aspect, Resolution, Mesh LOD offset, Rotation, Offset, Edge fade, Height from the material height map / normal alpha, Material list + seasons, Dynamic LOD) and `generator.fin` (flap with base ring on the skin: Size, Width, Flip, Style, Start angle, Roll, Fold, Curl, vertex noise, Scale X / Y / Z, Puffiness, Match surface, wind Ripple scale, Material list + seasons, Dynamic LOD). Both reuse the Knot placement and skin code (`collectPlacements`, `knotFrame`, `parentSkin`), the shared Generation tab (Knockout, Masks), split-safe parents, per-vertex parent wind, `decorations` statistics group, instance keys and project format (new node types only). Procedural default maps `surfaceDetailMaps` (knot patch, lichen flap, fungus shelf). `tests/decalFin.test.ts`.
- **Dynamic tree LOD (T14, roadmap R18).** Tree > LOD > Dynamic LOD: Enable, Mode (Manual / Screen area), LOD value, Levels (export, default 4) and the keep curves Branches / Leaves / Fronds / Decorations plus Grow scale. New pure module `src/lod/dynamic/`: importance analysis (26-ray exposure over a density grid, size for branches, generator Weight, seeded ties), continuous per-node scales (nodes shrink to their spine / attachment point before they are removed, surviving leaves grow to keep the area), mesh transform without re-running the graph. Per-generator LOD properties Weight, Optimization, Length segments, Radial segments (LOD tab; neutral defaults). Viewport: toolbar LOD popover (Enable, Screen area, LOD value, live triangle count) and a corner indicator. Export: with Dynamic LOD on, level k is the LOD value k / (n - 1), the manifest and the dialog report triangles per level and the interior removal share. `tests/dynamicLod.test.ts`, `tests/dynamicLodReal.test.ts`.
- **Seasons (T13, roadmap R20).** Tree > Season (slider 0..1, *Show dropped leaves*, *Export dropped leaves*), a Season popover on the viewport toolbar (undoable, drag merges) and the Lighting panel share one command (`app/seasonControl.ts`). Branch / Trunk / Root / Leaf / Frond / Decoration / Knot / Mesh get Material > Season (Start offset, Time scale, Descendant offset, Gravity, Drop time); the transition value is computed per node and element with seeded RNG (`src/seasons`), Material Set members are chosen by weight x Season curve (set-level Override season), branches droop by Gravity x transition, finished leaves are drawn on the ground (flagged scene entries, no wind, exported only on request), new Season Light / Season Wind forces with gizmo arrows, the season is stored in the project, the scene and the export manifest, and Oak / Maple / Birch presets carry Spring / Summer / Autumn / Winter sets. Defaults are neutral. `tests/seasons.test.ts`.
- **Leaf collision removal (T12, roadmap R19).** New pure module `src/generators/collision/` (uniform-grid broad phase over leaf spheres, sphere / oriented-box / exact triangle-triangle narrow phase with an alpha-aware hook, skeleton-capsule and branch-triangle tests, greedy priority resolution with ties broken by id, Remove / Shrink / Move). Tree > Collision: **Leaf collision removal** (None / Low / Medium / High), **Use spherical tests on leaves**, **Cluster plane overlapping** (XY plane). Leaf / Batched leaf > Post > Collision: Priority (curve), Sphere threshold, On collision, Test against, Parent. A post pass of the evaluator (after all nodes, before the scene is assembled; cancellable, time-sliced, cheaper at LOD > 0, memoised by settings + node keys); the host shows the plain tree first and the result pops in. The viewport statistics list the removed leaves. All defaults off / neutral: old projects are unchanged. `tests/leafCollision.test.ts`.
- **Species presets overhaul (T11).** All 16 species now use Displacement > Bark (style / depth / scale from the T07 bark recipes, maturity so twigs stay smooth), the Organic profile with radius noise, buttress fins, collar swell and natural forks (waist / neck swell / valley / ridge / dominance / lateral chance); radial sides >= 32 on trunks and main limbs (64 on hero trunks). Three **Realistic** hero presets (Oak, Birch, Pine; `hero` flag, 512 px bark maps) were added; Oak (Realistic) is the first card of the Welcome screen. Trunk softness index improved by 25 - 55 % for all broadleaf / conifer species. Preset thumbnails are rendered at run time from the graph (revision `b2` forces a refresh). `tests/presets.test.ts` (graph validity against the registry, budget, determinism, softness gate), `tests/windSeams.test.ts` (in-node seams strict, cross-node contacts 0.5 % for relief presets), `qa/baseline-pre-t11.json`, `docs/REALISM_TARGETS.md`.
- **Natural fork behaviours (T10).** Skin > Splits gains **Fork type** (Y / Lateral), **Dominance** (dominant leader: the fat half continues the parent direction down to 25 % of its Spread, the skinny half leaves at its full Spread with a smaller radius, pipe model kept), **Lateral chance** (per-fork seeded mix of Y and lateral forks) and Skin > Split shape gains **Included bark** (narrow V crevice, ridge, darker valley AO). A lateral fork is a branch-like fork (slight kink + clearly thinner side branch) with an implied neck swell / ridge / valley fillet. Variance on Dominance, Lateral chance and Included bark. All defaults neutral: old projects are byte-identical. Trifurcation is not implemented yet. `tests/splitT10.test.ts`.
- **Bark flows through the fork (T09).** The crotch rings of a split are now displaced with the parent's own coordinates (outline column j = parent vertex j + phase, arc length, lineage, circumference), so Bark / Main / Fine / Shape / Flares continue from the parent around both lobes without the smooth band; a splitting parent's last ring is no longer faded to zero. An extension that continues a displaced half carries the same pattern frame, does not fade in and gets the identical displacement at the shared ring. Its frames are rolled to the half's ring phase, its first ring is shared by index with the crotch's open-end ring when both are meshed together (otherwise the snap is exact and shifted), and it has exactly N / 2 vertices per ring at every LOD. The crotch colour blends from the parent to the lobes. Odd U tile counts keep the even-tile rule (raised + node warning), documented with the SpeedTree rule in `docs/SPLITS.md`. `tests/splitContinuity.test.ts`.
- **Split v2: a natural figure-8 fork (T08).** New **Skin > Split shape** (Trunk / Branch / Root): **Waist**, **Neck swell**, **Valley radius**, **Ridge** (+ **Ridge length**), **Stretch**, **Ease**. Each inner ring of the fused crotch becomes a smooth G1 figure-8 (lobe circle, rolling-ball valley fillet, lobe circle; `generators/split/forkOutline.ts`) instead of two arcs meeting in a cusp; topology, ring 0 (parent's real ring) and the open-end circles are unchanged. Any non-neutral value also switches on curvature-adaptive ring spacing (`splitRingParam`, denser near the parent and the pinch), at least 12 transition segments, a flat first 15 % (section normals within 2 degrees of ring 0), smooth normals across the filleted valley and a darker valley AO (`valleyAoFactor`). Defaults are neutral: old projects and all old tests are byte-identical. The T04 waist measure now uses the widest chord on each side of the neck instead of the chord at the skeleton path centre. QA report: new "Fork" section (default vs natural set). `tests/splitT08.test.ts`.
- **Procedural bark PBR maps (T07).** `barkMaps(style, base, seed, size)` in `presets/procTextures.ts` builds colour, normal (height in alpha), AO, roughness and height from ONE tileable height field (the T05 bark styles; Sobel normals, blurred-cavity AO, crevice roughness; 256 px, 512 for hero). `BARK_RECIPES` (13 families: broadleaf, conifer, pine, birch, willow, palm, acacia, baobab, dead, shrub, cactus, bamboo, sapling) + `barkMapsFromRecipe`. 14 species presets now embed the set in the Color / Normal / AO / Gloss slots. Normal maps are decoded exactly (new `textures/pngDecode.ts`) and uploaded with renormalised CPU mips (`textures/normalMips.ts`). Displacement > Source = Material falls back to the alpha channel of the Normal map when the material has no Height map, so geometry and normal map agree. `tests/barkMaps.test.ts`.
- **Organic trunk / branch profile (T06).** New **Skin > Irregularity** (Trunk / Branch / Root: Amount as RMS fraction of the radius with a curve along the branch, Scale in metres, Seed, Along parent curve; a second octave at 3x frequency / 0.4 amplitude, applied to the spine radius so children and welds see the real radius; faded before a split). New cross-section **Profile > Organic** (oval + 3rd and N-th harmonic whose amplitude, phase and orientation drift along the length, Drift length, Oval, Grain twist in degrees per metre on top of Spiral). **Skin > Junction > Collar swell** (smooth raised shoulder at a child's base, bounded by swell x child radius). **Shape > Buttress** (Count, Height, Length, Thickness: flat-ridged fins with concave sides at the base of a branch without parent; never below the base z). All defaults are neutral (0 / Round): old projects are unchanged. `tests/organicProfile.test.ts`.
- **Bark displacement source (T05).** Displacement > Source gains **Bark** with a style (Furrowed, Plated, Fibrous, Lenticel, Rings, Scaly) and the new **Bark** section: Depth (fraction of the local radius), Scale (metres), Stretch, Warp, Crevice (V-shaped vs flat-bottom, through the Sharpness LUT machinery), Maturity (smooth twigs -> deep old trunks: radius smoothstep + curve along the branch) and Seed; Subdivision > Max vertices caps the auto-subdivision per branch. The pattern is periodic around the branch and keyed on arc length + a lineage seed (split halves / extensions continue their host), and fades at junction / continued bases and tips. Auto-subdivision follows the feature size (>= 4 vertices across the narrowest feature). All defaults are neutral (Depth 0): old projects are unchanged. `tests/barkDisplace.test.ts`.
- **Realism QA harness (T04).** New pure module `src/qa/` (`surfaceMetrics`, `profileMetrics`, `forkMetrics`, `windSeamMetrics`, report helpers) measures softness index / dihedral angles, circularity, radius roughness, silhouette deviation, fork cross-sections (waist ratio, pipe-model area, valley curvature, simple outlines, ring 0 normal jump, open-end regularity) and wind seams. `QA_REPORT=1 npx vitest run tests/qa --maxWorkers=2` evaluates all 16 presets (seeds 1, 2) and writes `qa/realism-report.md` + `qa/baseline.json` (and git-ignored OBJ / SVG dumps in `qa/out/`). Goals and baseline in `docs/REALISM_TARGETS.md`. No behaviour change.
- **Wind: weld rings, caps and foliage attach continuous with the parent (T03).** The first rings of a welded child take the wind (w0, w1, w2, phase, phase1, pivot) of the parent skin vertex they sit on and fade into the child's own values with the same `weld.blend` curve as the normals (phases along the shorter arc). The first ring of an extension / cap of a split half copies the half's end-ring wind exactly. Leaves, cards, knots, decorations and cluster instances interpolate the parent's wind at their attach position instead of snapping to the nearest skeleton point. New pure audit `auditWindSeams` (`src/viewport/wind/windAudit.ts`: coincident vertices, near-contact of different generators, optional vertex-on-surface check; max / mean gap, worst vertex, generator ids) and the View mode **Wind weights** (w0 / w1 / w2 as RGB, off by default). `tests/windSeams.test.ts` audits all 16 presets (seeds 1-2, strength 2): wood seams < 0.2 % of the tree height.
- **Wind: one phase per wind level (T02).** New per-vertex channel `windPhase1` (skeleton attribute, `MeshData.wind.phase1`, GLB `_WIND_PHASE1`, three.js attribute `windPhase1`): the phase of the level-1 ancestor. The branch-level sway terms of the shader and of the CPU reference use it, so a child's base moves exactly with the parent point it grows from (no gap at generation >= 2). Level <= 1 branches create their own (Animation > Phase variance now takes effect, default unchanged), deeper branches, split halves, extensions and foliage copy it. Old data without `phase1` falls back to `weights[3]`.
- **QA tooling and debug overlay for splits (S8).** `meshQuality` reports boundary / non-manifold edges, degenerate triangles, NaN, smallest triangle angle, UV stretch, duplicate vertices and the normal jump near junctions; the tests assert it for every preset, trunks that always split at three depths, branch and root splits, extension chains and caps. New view toggle **Show open ends** (off by default) draws a ring, a direction arrow and the index (1 / 2) of every open end, coloured fat / skinny / break / bottom. New page `docs/SPLITS.md` (topology, open ends, lineage, UV rules, how to extend, known limits).
- **Split generator > Split parents only** forks only the parents that already split, never their halves.

### Changed
- **Wind: split halves and extensions inherit the wind of their parent (T01).** The two halves of a split, split-extension halves and Extend-parent branches used to restart their wind weights at 0 with a new random phase, so with wind enabled they separated from the trunk and tore the skin at the fork. They now inherit the complete wind vector and the phase exactly at the attach point and keep growing the parent's wind level (`w = a + (1 - a) * t^1.5`); the crotch rings blend into each half's wind. Regular children are unchanged (bit-identical).
- **Roots anchor on the ground base only (S7).** A Root generator under a Trunk no longer grows roots on the split halves or extensions of the trunk (they used to hang in the air at the fork). Roots start only on primary spines without a parent; with several trunks every trunk gets its own roots; splits above no longer change root count or positions. **Extend parent** is now available on Root (*Bottom* continues the trunk's base ring seamlessly) and Root nodes can be extended / capped. Roots split with the shared engine: new *Split advanced > Down bias* (Root default 0.4) and Root *Area exponent* default 2.3. Lateral roots never leave split halves of a root parent.
- **One split engine for Trunk, Branch and Root (S6).** The old polyline fork (*Tip behavior > Fork*, *Split chance / spread / balance / position / max depth*) is gone; everything splits through *Skin > Splits* (fused crotch, pipe model, lateral balance). Old projects migrate automatically: Split chance / spread / balance map onto *Chance* / *Side 1, 2* / *Balance*, *Fork* becomes Taper with Chance 1, Root keeps its old defaults (Chance 0.3, 30 degrees). Any Branch generator can split. A welded branch that splits keeps its weld only at its base; its halves and extensions are never welded. Spine instances carry a lineage tag (`spineOrigin`: primary / split half / extension). Chance, Balance, Side 1 / 2, Expand and Smooth now have the variance toggle, each on its own random stream (Splits > Seed re-rolls only the splits). The radial count of a splitting parent is made even after all Resolution / LOD scalars. Oak, Maple, Birch, Willow and Acacia got natural split settings; Spruce and Pine stay monopodial.
- **Cap and extension polish (S5).** A *Cap* no longer closes an open end that a sibling Branch already extends (a Cap on *Any* closes only the remaining ends; a Cap naming exactly the extended type still may; of two Caps the first one wins). Several extensions on one end (*Count* 3+) lean the normals of their first rings towards the cylinder of the shared end (*Normal smooth*), so the bundle has no visible seam. *Extension style > Manual (match)* and *Manual (match u only)* now add the node's own U / V offsets to the parent's values. Old projects load unchanged.
- **Branch > Extensions with several extensions per end.** *Count* 2 on one open end is built as a virtual split: one short fused stub continues the end and forks through the fused crotch into two extensions (no gap at the junction); *Count* 3 and more start on a small Fermat spiral inside the end disc and fan out by *Spread*. Every extension gets the radius `end radius x count^(-1/e)` (*Area exponent* from Splits). Extensions take the end's radial count. *Length scale* is 0.1-3, *Spread* and *Radius* default to 0, *Displacement scale* is 0-2. The **Cap** is now an extension of its end: it uses the end's exact radius, radial count (N / 2 on a split half), ring frame and U tiling, adds no buried ring and works with every Extend parent type. Old projects load unchanged (missing values use the defaults).
- **Extend parent** follows one rule table (`selectOpenEnds`): an unsplit parent is a single *Split 1* / *Fat* end (never *Skinny*), *Breaks only* needs a real break, *Bottom* extends the base of the parent pointing back along its direction (it is no longer pruned underground). An extension starts exactly on its open end (position, direction, frame and radius), and a child spine that wants another direction blends in over the first 1.5 radii, so there is no kink at the junction. Extensions are never pruned. The *Type* and *Count* controls are disabled with a tooltip when the parent is not a Branch generator; chains deeper than 32 generations log an error instead of growing. Old projects load unchanged.
- **Split junction shading, UV and material blend.** The fused crotch now has clean normals: computed on the logical vertex set (no seam line at the fork), area x angle weighted, relaxed across the transition, the open ends carry the plain cylinder normal and a mild light seam reduction (Gaussian, 1.5 parent radii) leans the normals of the rings around the fork toward the axis. *Smooth > Inner* = 1 averages fully, 0 keeps a crisp crease (split normal fan). The first crotch ring is the parent's last ring (no duplicated vertices except the UV seam and the crotch fans). Each half carries half of the parent's U tiles and the V of the open end, so an extension with *Extension style > Automatic* continues tile count, U offset and V without a jump. Extensions with a material different from their parent's blend from the parent material over *Skin > Extensions > Blend length* (new, 0.5-8 parent radii) with *Contrast* and *Noise* (reuses the weld blend channels; Inherited writes nothing). The blend is exported as the glTF attribute `_BLEND`. Old projects load unchanged (new parameters have defaults).
- **Fused crotch mesh.** A splitting parent and its two halves are now one continuous skin with pair-of-pants topology (`src/generators/split/crotchMesh.ts`, `src/geometry/splitCrotch.ts`): the parent's ring of N vertices turns into a figure-8 and then into two tangent rings of N / 2 vertices, the crease starts with zero depth, the bark U of every vertex is kept across the fork and V continues from the parent. Smooth > Inner fills the crease, Smooth > Outer relaxes the outer bend, Expand Side 1 / 2 widens each half in the middle of the transition. Splitting parents use an even radial count (>= 6 in the mesher). No gap, stub or second tube start at the fork any more. Old projects load unchanged (missing Expand / Smooth attributes use the defaults).
- **Splits** use a natural split model (`src/generators/split/splitModel.ts`): the parent spine continues as the shared body through a transition (3.5 radii, bounded by 8-35 % of the length) and both halves leave it along a smooth Hermite path, ending as two exactly tangent open ends. Radii follow the pipe model with an *Area exponent* (new advanced setting, default 2), the fat half bends less (lateral balance), Side 1 leans away from the tree centre with a seeded +-15 degree jitter. Spread defaults are 22 degrees (0-80), Expand ranges 0.5-2. A branch that splits needs an even U tile count: an odd count is raised to the next even number and the node reports it as a warning. Open ends now carry kind, frame, U tiles / start and the parent spine id. Old projects load with the new defaults for missing values; the junction mesh itself follows in the next step.

### Fixed
- **A generator under a splitting Trunk, Branch or Root is no longer repeated for the two halves.** A split counts as one spine: Branch, Split, Leaf, Frond, Decoration, Knot and the other placement generators run on the primary spine only, up to the start of the shared transition. The halves stay parents only for Extend parent and Cap.
- **No gap between a split parent and what is attached to it.** Children are placed on the true tube (not inside the fork or on a half's centre line), and the first ring of an extension or a cap is snapped vertex for vertex onto the real end ring of the half it continues (a Cap on both halves of a fork leaves no open edge).
- CI/deploy no longer fails on `tests/shell.dom.test.ts` timeouts: WebGL renderers are created through one factory that returns `null` without WebGL (the viewport then shows a "WebGL unavailable" notice instead of throwing), tests never construct a real renderer, and Vitest uses a 30 s per-test budget with at most 2 workers on CI.

### Added

Knots count as decorations. Old Knot nodes are migrated on load.
- **UV Mapping** tab on Branch (and the Extensions UV list): Style (Unrestricted / U locked / U and V locked), Extension style, U (Absolute, + Relative, Offset with variance, Fractional Enable / Auto / Value, Twist Amount / Random flip), V (Style Absolute / Relative (keep aspect ratio) / Relative, Anchor, Scale, Skew correction, Pinch, Offset with variance) and Tiling (Style Tiling / 0-1 patches choose one / use all, Optimize segments, V tolerance, Seed). Extensions continue their parent end without a weld ring, collar or cap. The **Cap** now closes exactly the open ends (broken branches and split sides) and follows Extend parent. Pure logic in `src/generators/split/`.
- Skin > **Welding > Blend** (Enabled, Texture, Texture scale, Contrast, Noise, Lighting curve): the bark map of a welded child fades into the map of its parent around the weld (per-vertex `weldBlend` / `weldParentUV` channels, two map samples mixed in the bark shader; other materials ignore it).
- Skin > **Radius** (Absolute, + % of parent, Clamp to parent, Length compensation, Length kill ratio, Light seam reduction, Roll, Smooth), **Clamp** (Min, Max), **Squash** (Amount, Rotate; welded children follow the flattened parent) and **Type & Visibility** (Type: Polygons / Spine only, the SubD entries are listed as not yet available; Visibility curve: branches above 0.5 get geometry). Pure logic in `src/generators/skin/`.
- Skin > **Welding** on Branch and Root: *Enabled* fuses the base of a child into the surface of its parent (the base ring lies exactly on the parent skin at any angle, a smooth blend of rings leads to the plain branch, normals fade from the parent's to the branch's), *Keep* (curve over the model height; welds below 0.5 are dropped), *Keep failed*, *Force ray casts* (rays against the real parent tube instead of the procedural cone), *Offset* (length of the weld part in branch radii) and **Spread** (*Amount*, *Upper scale*, *Lower scale*: widening at the weld site, a web where branches meet). Failed welds remove the branch unless *Keep failed* is on. The number of rings uses Segments > Length > Weld scalar. Off by default; pure logic in `src/generators/weld/`.
- Spine > **Noise** has *Early* (Amount, Turbulence, **Threshold** with a profile curve: where the early noise starts and ends) and *Late* (Amount, Turbulence, Smooth, Seed) blocks; the Late Seed changes only the late noise. New Spine sections **Jink** (Amount, Absolute, + Relative, Uniformity, Seed: straight runs), **Path** (Amount, Profile curve = one tile, Twist, Length, Offset with variance) and **Break** (Chance, Spot, Seed). Broken branches write an `openEnd` skeleton attribute that Extend parent > Breaks only (and Caps) read. Pure logic in `src/generators/spine/` (`noiseMath`, `jinkMath`, `pathMath`, `breakMath`).
- **Segments** tab on Trunk / Branch / Root / Spine: Accuracy (exact points of the high-resolution spine), Influence, Scalar; Length (Style Default / Legacy, Absolute, + Relative, Relative basis: Length only / Length/radius ratio / Parent's length segments, Weld scalar, Optimization) and Radial (Absolute, + Relative, Relative basis: Radius / Parent's radial segments). The radial count is stored per branch (`radialSides` skeleton attribute).
- Spine > Length: Match one V tile, Stop shape control, Shape scale; Orientation: Unify, Alignment blends a random up with the world up, Weld start for Spine only branches; Parent Curl Up / Right / Out rotate around the parent's axes; Zigzag Segment length (Absolute with curve, + Relative); Prune Interior / Up / Down / General / Ground are 0..1 strengths with curves.
- Shared Generation properties on every generator: **Boundaries** (First, Last, Clip removes nodes pushed outside the range), **Common** (Active over the level of detail, Pass with an error badge when lower than an ancestor, Rotation, Position, Sink with variance, Pruning curve), **Extend parent** (None, Any, Split 1, Split 2, Skinny, Fat, Breaks only, Bottom + Count; Branch / Cap / Leaf / Batched leaf), **Knockout** (Amount + Resolution), **Force containers** (Include / Exclude by Force node name; Force nodes got a *Volume* section: Sphere or Box), **More** (Click place, Mesh alignment, Size scalar that is handed down to all children) and **Masks** (any number of masks from the Masks panel). The pure logic lives in `src/generators/common/`.
- Generation modes for every generator (Trunk, Branch, Root, Spine, Leaf, Batched Leaf, Mesh Instance, Cap, Cluster): Absolute, Proportional, Absolute steps / Proportional steps (Steps, Per step, Spread, Roll, Balance), Phyllotaxy (Internode length in metres from Last towards First; Style Opposite distichous / decussate / random, Alternating distichous / random, Whorled; Children per node, Spread, Spiral, Limit, Align style), Interval (Frequency with a profile curve, Count, Spread, Spiral, Limit, Align style, Balance), Bifurcation (Count, Threshold, Spread), Flood and Parent. Only the parameters of the chosen mode are shown; *Classic* is listed as a disabled legacy entry. The layouts live in the pure module `src/generators/modes/` and every node publishes its `side` (+1 / -1) and `groupIndex`.

### Changed
